# 提色施法审阅工程

明亮木盘第一阶段的 964 个原始元素保持不变，沿用用户在游戏主 JSON 中的握姿。默认预览为黄、蓝两色，第三槽留空。

`调色盘_明亮木盘_提色施法_分组动画.bbmodel` 含待机与 1.6 秒施法两段可编辑原生关键帧。施法过程为持盘倾斜、颜料升起、色流汇聚成一枚现有颜料小球、球飞出、空盘收势。槽色、七段色流、汇聚小球和湿亮屑均单独分组；第三槽预留。编辑模式中可以隐藏「07_施法_提色与汇聚」观察盘体，待机动画会自动隐藏该组。

小球直接复用当前资源包已采用的 132 元素颜料球形状，不重新设计追踪实体。2026-10-09 已按用户要求接入游戏：单枚实际追踪实体在提色阶段隐形等待，第 22 刻接续手上的小球并开始追踪。伤害、颜色强化、冷却、自毁条件与原有小球尺寸保持。待机 20 帧、施法 32 帧，由原生母版导出；盘体整体旋转采用合法 display 变换，保持连续倾斜和盘体结构。原生动画不会仅凭放入资源包而自动在 Java 原版播放。

完整静态 `显示调整示例/assets/palette/models/item/palette.json` 具有 display 和所有待机可见元素，默认黄蓝为 663 个立方体，可用于统一调整位置；原生母版含隐藏颜色及施法特效为 1,232 元素、127 个分组、4 张内嵌贴图。完整显示模型和动画母版用途不同。

分镜与 GIF 均由交付母版的几何、UV 和关键帧渲染。检查包含原始元素保持、UUID/分组归属、关键帧引用、静态 Java 坐标/旋转及 display 一致。`游戏产物回渲.png` 从游戏产物的 JSON、PNG 和实际 display 回渲，未叠加预览特效。

部署入口：`D:/数据包/sweetdream_rp/assets/palette/models/item/palette.json`。修改此文件的整体 display 后双击根目录「部署到存档.bat」，会同步所有颜色与动画部件；三轴 scale 保持相同。此目录的显示调整示例是导出时的副本，后续调整以资源包内的主 JSON 为准。

645 个文件已同步测试存档且哈希一致，全包静态检查 0 问题。常态示例 663 元素、双色施法峰值 828 元素；去重后资源约 2.6 MiB。16,640 组颜色/帧/视角组合及运行时驱动已离线验证。游戏内运行 `/reload`，再 F3+T；真实游戏观感、网络时序及 Blockbench 软件内打开检查仍待实测。详细部署与接入证据见「游戏接入检查.json」。
