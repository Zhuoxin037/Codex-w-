## 怎么装进游戏

两个包**必须同时**放进存档的 `datapacks` 目录，缺一个都不行（应用层依赖前置包）。
资源包 `sweetdream_rp/` 另外丢进 `resourcepacks/`：

```
<saves>/<存档名>/datapacks/
├── manacore-1.0.0/
└── sweetdream/
```

然后 `/reload`。**这两个目录是复制进去的，不是链接** —— 在本目录改完代码，
必须重新复制一遍再 `/reload`，否则游戏里跑的还是旧版本。

本机的游戏目录：
`D:\PCL 正式版 2.10.0\.minecraft\versions\1.21.5-Fabric 0.16.10\saves\<存档名>\datapacks\`
（注意存档在**版本目录**下面，不在 `.minecraft\saves`。）

**省事的办法：双击 `部署到存档.bat`。**

- 直接双击 → 部署到默认存档 `测试包体`
- 把别的**存档文件夹**（里面有 `level.dat` 的那个）拖到它图标上 → 部署到那个存档
- 它用 `robocopy /MIR` 镜像复制，所以源里删掉的文件目标里也会跟着删，
  不会留下旧版本的残留函数；部署完进游戏 `/reload` 就行
- 拖错目录会直接报错退出，不会乱建文件夹

> `部署到存档.bat` 只是个 ASCII 启动器，真正的逻辑在 `deploy.ps1`。
> 为什么不写在一个 `.bat` 里：**中文写进 `.bat` 会被 cmd 按 GBK 解码成乱码**，
> cmd 会把乱码碎片当命令执行。所以启动器保持纯 ASCII，中文放在
> 带 BOM 的 `.ps1` 里（这个坑实测踩过）。

## 约定

| 东西 | 用什么 | 说明 |
| --- | --- | --- |
| 命名空间 | `sweetdream:` | 应用层的函数、进度、标签 |
| 存储 | `zx:` | `zx:data`（存东西）/ `zx:work`（临时）/ `zx:out` / `zx:config` |
| 计分板 | `zx.meta` | 应用层内部用 |
| 前置包 | `manacore:*` | 那是它的地盘，别混用 |

玩家数据一律**按 UUID 分键**存在 `manacore:players."<uuid>"` 下面，
所以每个人的魔力、攻击、冷却都是独立的。

改完代码跑一遍静态自检 `.workbuddy/check.py`（**42 项，必须 0 问题**）。它会抓历史上
真出过事的那几类，比如：

1. 含 `$(变量)` 的行必须以 `$` 开头；不含变量的行绝对不能加 `$`
2. `data get/modify/remove entity` 的选择器必须是**单个实体**（`limit=1`）
3. 进度奖励函数第一行必须 `advancement revoke @s only <自己那条进度>`，
   且自撤销型进度必须列进 `lib/rearm`（漏了会**永久静默失效**）
4. `function` / `schedule function` 引用的目标文件必须存在
5. 伤害触发型进度必须限定 `minecraft:is_player_attack`，否则技能伤害会一起算进去
6. 物品描述的版式必须等于 `lore_fmt.py` 的输出（数字留白 / `×` / 罗马数字）
7. 技能伤害只能走三条倍率通道（`max_mana_mul` / `attack_mul` / `other_mul`）——
   不许再把面板读数塞进 `base_attack`；口径表（`lib/skill_mul/def`）必须和技能文件
   对得上；超限三条通道都要派发（见 `使用教程.md` 7.1）

## 已知问题

- **玩家 UUID 只算出 8 位**（例如 `0000000f`），正常应该是 36 位。
  入口在 `manacore-1.0.0/data/manacore/function/internal/uuid/build.mcfunction`。
  目前不影响使用（所有键都用同一个值，自洽），但这是个真的要修的 bug。
- **⚠️ 新增伤害类型 / 改附魔后必须"退出世界重进"，`/reload` 不补。**
  `damage_type` 和 `enchantment` 是**注册表**类内容，只在进世界时加载。
  本包的 `sweetdream:skill`（技能默认类型）、`sweetdream:true_damage` 就是新增的；
  没重进世界时相关 `/damage` 会**静默失败** —— 不报错、不写日志，只表现为
  "技能放出来了但一点伤害都没有"。**症状必然是"别的都正常，就那几处哑火"。**
  寒鸦的命中判定完全靠附魔「霜矢」，同理：改完要重进世界 **+ 重新 give 一把**
  （老物品不会自己长出附魔）。一秒判定：`/function sweetdream:debug/true_damage`、
  `/function sweetdream:debug/cold_crow`。
  应急开关（万一类型没生效）：
  ```mcfunction
  /data modify storage zx:config damage_type set value "minecraft:player_attack"
  /reload
  ```
  代价是多段伤害又会撞无敌帧。
- ~~原版没有"绕过无敌帧"的伤害类型标签~~ **已解决。** 原版其实**有**这个标签：
  `minecraft:bypasses_cooldown`（1.21.5 里由 `DamageTypeTags` 注册，只是原版一个
  伤害类型都没往里放）。sweetdream 注册了自己的 `sweetdream:skill` 并挂进这个标签 ——
  技能伤害**不再被受伤无敌帧吃掉**（照样吃护甲 / 保护附魔 / 抗性）。
  副作用：同一 tick 的多段伤害现在会全部结算，击退也会叠加，以后做平衡按"多段全额生效"算。
- ~~武器放副手右键会顶掉主手的武器~~ **已解决。** 现在主手 / 副手各备份一份
  （盔甲架两个槽位），触发那一刻记录用的是哪只手，回手按标签分叉写回对应槽位。
  自查：`/function sweetdream:debug/offhand`。
- ~~寒鸦按射手保存"最近一发"，在途旧箭会被后发覆盖~~ **已解决。** 改成**逐箭快照**
  （每支箭随身带自己那一发）。自检：`/function sweetdream:debug/cold_crow` 的 ⑤。
- ~~幻昼可能把效果施加给错误的生物~~ **已解决。** 改用生物自己的 `last_hurt_by_player`
  精确匹配，`HurtTime` 10/9 只负责钉住"就是刚才这一下"。
- ~~概率与坐标 / 攻击节奏绑定~~ **已解决。** 新增 `sweetdream:lib/rnd`（全局 LCG），
  幻昼的两次 20%、异彩的"5 选 2"全部改从它取样，和坐标、攻击间隔彻底脱钩。
- ~~副手引梦镰会扣费却不释放~~ **已解决。** 在消耗那一刻判定用哪只手并写进施法快照，
  后续全程按它走。
- **⚠️ 一行命令解析不了 = 整个函数不可用（不是"少那一句"）。**
  普通函数会**加载失败**（日志 `Failed to load function ...`），宏函数则是
  **整个函数一条命令都不跑**。踩过这几种：
  1. **dust 粒子必须写花括号选项**：`particle minecraft:dust{color:[r,g,b],scale:s} …`
  2. **`tellraw`/`title` 组件里别混进未转义的 ASCII 双引号**（中文引号用 `「」`，或写 `\"`）
  3. **只认玩家的命令不能配 `@e`**：`tellraw`/`title`/`clear`/`give`/`xp`/`advancement`
     的"目标"在命令树里是 players-only，写 `@e[...]` 是**解析期**失败
  4. 参数之间出现**连续两个空格**、`store result score` 多写了 `scale`
  `.workbuddy/check.py` 会抓这几类（第 9、10、12、21、22 项）；
  **因为解析失败会连坐整个文件，改完务必看日志有没有 `Failed to load function`。**
- **别把"替换"写成"新增"**：给某一行加包装时旧那行没删掉，就会前后脚跑两遍，
  而且不报错、日志干净。`/damage` 被执行两遍 = **全包所有伤害翻倍**。
  check.py 第 11 项专抓这个（有意重复的在那行上面写 `dup-ok: 理由` 豁免）。
- **★ 改了源目录 ≠ 游戏里生效**：让用户进游戏测之前必须重新部署（`部署到存档.bat`）。
  报错日志里的**行号和源文件对不上**，就是"游戏读的是旧版"的最强信号 ——
  先 `diff -rq D:\数据包\<包> "<存档>\datapacks\<包>"`，别急着当代码 bug 查。

## 仓库里不放什么

数据包本体（`manacore-1.0.0/`、`sweetdream/`、`sweetdream_rp/`）和这几份文档进版本控制；
下面这些是本地开发用的，已经在 `.gitignore` 里排除：

- `.workbuddy/` —— 离线工具链（`check.py`、`lore_fmt.py`、各种生成器与渲染器）、
  开发笔记、渲染产物（二十多兆）
- `logs/` —— 模型对比截图
- `*.bak-*` / `*.broken-*` —— 备份与坏版本存档

> 注意 `sweetdream_rp/**/optimized/` **不是**临时产物，是模型真正引用的贴图，别删。

## 新开一个对话怎么接着干

把下面这段直接发给新对话就行：

```
工作目录是 D:\数据包，先读 D:\数据包\README.md 和 D:\数据包\使用教程.md，再动手。
这是两个配套的 Minecraft Java 1.21.5 数据包：manacore-1.0.0（前置框架）和
sweetdream（应用层），外加资源包 sweetdream_rp。改完记得跑 .workbuddy/check.py
做静态自检（必须 0 问题），并用中文详细注释。
```

新对话不会记得我们聊过什么，**文档就是交接内容** —— 所以约定、踩过的坑、
当前状态都写在这几个文件里。要是想到什么该记的事，先补进文档再走。
